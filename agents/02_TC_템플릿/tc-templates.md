# TC 템플릿 (팀 표준 양식)

시트는 **TestCase / Checklist / Data** 3개다.
답변은 파일로 만들지 않고, 아래 "채팅 출력 형식"대로 엑셀 시트와 같은 순서·같은 컬럼의 표로 보여준다.

---

## 0. 공통 규칙

### Category (분류)
| 컬럼 | 의미 | 예시 |
|---|---|---|
| Category 1 | 대분류 | 로그인 |
| Category 2 | 중분류 | 소셜 로그인 |
| Category 3 | 소분류 | 카카오 |

- **병합 규칙 (TestCase · Checklist · Data 공통)**
  - Category 1(대분류)과 Category 2(중분류)는 위 행과 텍스트가 같으면 병합한다. 중분류는 같은 대분류 안에서만 병합한다.
  - Category 3(소분류)은 병합하지 않는다. 값이 같아도 행마다 적는다.
  - 채팅 표에서는 그룹의 첫 행에만 대분류·중분류를 적고 아래 행은 비운다. 엑셀 파일에서는 실제로 셀을 병합하고 세로 가운데 정렬한다.
  - 참고: 병합된 열은 엑셀 필터에서 첫 행만 걸린다. 필터가 필요하면 병합을 풀고 쓴다.

  채팅 표 예시
  | ID | Category 1 | Category 2 | Category 3 | 확인항목 |
  |---|---|---|---|---|
  | 1 | 천랑 장비 | 천랑의 반지 | 거래 | 천랑의 반지 거래소 등록 불가 확인 |
  | 2 | | | 분해 | 천랑의 반지 분해 메뉴 미노출 확인 |
  | 3 | | 천랑의 활 | 판매 | 천랑의 활 상점 판매 불가 확인 |
  | 4 | BM | 천랑 성장 패키지 | 구성품 | 천랑 성장 패키지 구매 시 강화석 100개 지급 확인 |

### 결과값 (Data / Result 컬럼)
드롭다운 값: `Pass, Fail, Block, N/A, Skip, -, Incomplete`

| 값 | 의미 |
|---|---|
| Pass | 기대 결과와 일치 |
| Fail | 기대 결과와 다름 → BTS Key에 이슈 번호 기입 |
| Block | 선행 이슈 때문에 진행 불가 |
| N/A | 해당 없음 (테스트 대상 아님) |
| Skip | 이번 차수에서 제외 |
| - | 미정 또는 보류 |
| Incomplete | 미수행 (기본값) |

- 처음 작성할 때 Data와 Result는 모두 `Incomplete`로 둔다.
- 상단 요약은 **Result 컬럼** 기준으로 집계한다.
- 진행률 = (Pass + Fail + N/A + Block + Skip + -) ÷ 전체

### 작성 어미 규칙
| 항목 | 규칙 | 예시 |
|---|---|---|
| Precondition (테스트 조건) | 번호를 매기고 **"~상태"**로 끝낸다 | 1. 로그인된 상태<br>2. 장바구니에 상품이 1개 담긴 상태 |
| Test Step (실행 순서) | 번호를 매기고 **"~확인"**으로 끝낸다 | 1. 장바구니 버튼 선택 후 화면 확인<br>2. 상품 수량 표시 확인 |
| Expected Result (기대 결과, TestCase) | **"~다."**로 끝낸다 | 장바구니 화면으로 이동되며 상품 수량이 "1"로 노출된다. |
| 확인항목 (Checklist) | **"~확인"**으로 끝낸다 | 장바구니 아이콘 선택 시 장바구니 화면 이동 확인 |
| 참고 사항 | **"~합니다."**로 끝낸다 | 보상 아이템이 많아 등급별 대표 아이템을 샘플로 정해 확인합니다. |

- 한 셀에 여러 줄을 쓸 때는 셀 안에서 줄을 바꾼다. (채팅 표에서는 `<br>`)

## 1. 시트 구조

### 공통 상단 블록 (모든 시트)
| 왼쪽: Test Result | 오른쪽: 테스트 정보 |
|---|---|
| Pass / Fail / N/A / Block / Skip / - / incomplete 개수 (COUNTIF 수식) | Spec Key |
| 진행률 (수식) | Document |
| | Data |
| | 참고 사항 (5줄 병합 영역) |

- 개수와 진행률은 엑셀 수식이 자동 계산하므로, 채팅 출력에서는 **테스트 정보만** 채워서 보여준다.

### TestCase 시트
| ID | Category 1<br>(분류 1) | Category 2<br>(분류 2) | Category 3<br>(분류 3) | Precondition<br>(테스트 조건) | Test Step<br>(실행 순서) | Expected Result<br>(기대 결과) | BTS Key | Data<br>(데이터) | Result<br>(결과) | QA Comment | Test Ver |
|---|---|---|---|---|---|---|---|---|---|---|---|

- ID는 1부터 순서대로 적는다.
- Data, Result 기본값 `Incomplete`. BTS Key, QA Comment, Test Ver는 비워 둔다.

### Checklist 시트
| ID | Category 1<br>(분류 1) | Category 2<br>(분류 2) | Category 3<br>(분류 3) | 확인항목 | BTS Key | Result<br>(결과) | QA Comment | Test Ver |
|---|---|---|---|---|---|---|---|---|

- 확인항목은 한 줄에 확인 포인트 하나만 적는다.
- Result 기본값 `Incomplete`.

### Data 시트
| ID | Category 1 | Category 2 | Category 3 | Precondition<br>(테스트 조건) | Test Step<br>(실행 순서) | Column 1 | Column 2 | Column 3 | ... | Column n | BTS Key | Data<br>(데이터) | Result<br>(결과) | QA Comment | Test Ver |
|---|---|---|---|---|---|---|---|---|---|---|---|---|---|---|---|

- 기획서에 적힌 **데이터 값(테이블, 수치, 보상, 확률, 가격, 문구 등)**을 그대로 옮겨 적고, 실제 값과 비교해 결과를 처리하는 시트다.
- `Column 1 ~ Column n`의 이름은 기획서 데이터 테이블의 컬럼 이름으로 바꾼다. (예: 아이템ID / 아이템명 / 가격 / 수량) 컬럼 수는 기획서 데이터에 맞춰 늘리거나 줄인다.
- 한 행이 데이터 한 건이다. 기획서 값은 **수정하거나 추정하지 않고** 그대로 옮긴다.

## 2. 채팅 출력 형식 (기본)

파일을 만들지 않고, 엑셀에 옮겨 적기 쉽게 아래 순서로 보여준다.

**① 시트 이름 제목**: `### TestCase 시트` / `### Checklist 시트` / `### Data 시트`

**② 테스트 정보 표**
| 항목 | 내용 |
|---|---|
| Spec Key | (기획서 키 또는 JIRA 키, 모르면 비움) |
| Document | (기획서 이름) |
| Data | (데이터 문서 이름, 없으면 비움) |
| 참고 사항 | (샘플링 기준, 테스트 범위·제외 범위, 확인 필요 사항을 "~합니다."로. 여러 개면 `<br>`로 줄 나눔) |

**③ 본문 표**: 위 시트 구조의 헤더를 **같은 순서, 같은 이름**으로 쓴다. 헤더의 괄호 한글(예: "(분류 1)")은 표가 넓어지지 않게 생략해도 된다.

TestCase 예시
| ID | Category 1 | Category 2 | Category 3 | Precondition | Test Step | Expected Result | BTS Key | Data | Result | QA Comment | Test Ver |
|---|---|---|---|---|---|---|---|---|---|---|---|
| 1 | 로그인 | 일반 로그인 | 정상 로그인 | 1. 회원가입이 완료된 상태<br>2. 로그아웃된 상태 | 1. 로그인 화면에서 ID/PW 입력 확인<br>2. 로그인 버튼 선택 후 화면 이동 확인 | 메인 화면으로 이동되며 상단에 "OOO님 환영합니다" 문구가 노출된다. | | Incomplete | Incomplete | | |

Checklist 예시
| ID | Category 1 | Category 2 | Category 3 | 확인항목 | BTS Key | Result | QA Comment | Test Ver |
|---|---|---|---|---|---|---|---|---|
| 1 | 우편 | 보상 수령 | 수량 | 우편 보상 수령 시 인벤토리 수량 증가 확인 | | Incomplete | | |

Data 예시 (Column 이름은 기획서 데이터 컬럼으로 교체)
| ID | Category 1 | Category 2 | Category 3 | Precondition | Test Step | 아이템ID | 아이템명 | 가격 | BTS Key | Data | Result | QA Comment | Test Ver |
|---|---|---|---|---|---|---|---|---|---|---|---|---|---|
| 1 | 상점 | 일반 상점 | 소모품 | 1. 상점 화면 진입된 상태 | 1. 상품별 가격 노출 확인 | 10001 | 체력 물약 | 100 | | Incomplete | Incomplete | | |

**④ 요약**: 시트별 작성 개수 / 대분류별 개수 / 확인 필요 사항 (표 아래 3~5줄)

- 행이 많아도 표를 나누지 않고 한 표로 이어서 쓴다. 대분류가 바뀌어도 같은 표 안에서 이어 간다.
- 비어 있어야 하는 칸(BTS Key, QA Comment, Test Ver)도 컬럼은 지우지 않는다. 엑셀에 그대로 붙여넣을 때 열 위치가 맞아야 하기 때문이다.

## 3. 테스트 관점 체크리스트 (참고)
- 입력값: 필수/선택, 공백, 특수문자, 이모지, 최대·최소 길이, 경계값(-1/0/+1)
- 상태: 최초 진입, 재진입, 뒤로가기, 백그라운드 전환, 세션 만료
- 네트워크: 오프라인, 느린 네트워크, 요청 중 끊김, 중복 선택
- 권한: 비회원/일반/관리자, 권한 거부
- 데이터: 0건, 1건, 대량, 페이지 경계
- 시간: 날짜 경계(월말·연말), 타임존, 서버 시간
- 캐릭터 단위 여부: 캐릭터를 바꾸면 확인 내용이나 결과가 달라지면 캐릭터 단위로, 같으면 공통으로 작성한다. 값만 다르면 Data 시트로 보낸다.
